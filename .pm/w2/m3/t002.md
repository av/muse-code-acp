## Objective

Prove the distinction is visible to a client that negotiates nothing, and that the negotiating client's metadata is unchanged.

## Context

- The reported case is a client with no Muse extension, so the deterministic cases must assert on `toolCall`, not on `_meta`.
- `src/tests/permissions.test.ts` has the multi-stage fixture scripts from m1 (`two-stage`, `three-stage`, `deny-at-stage-2`); reuse them rather than adding new ones.
- `src/tests/muse-sdk-multistage-live.test.ts` covers the real host and is already in `test:muse-loopback`.
- A regression here is silent, so assert on difference explicitly: the set of rendered titles must have as many distinct values as there are prompts.

## Steps

1. In `permissions.test.ts`, assert that a two-stage run produces two distinct `toolCall.title` values, each naming its stage position and total, for a client advertising no `_meta` capability.
2. Assert the three-stage run produces three distinct titles in source order, and that the single-stage approval title is unchanged.
3. Assert a negotiating client still receives the same `muse/approval` stage metadata as before.
4. Extend the live suite to assert distinct rendered titles on the real host for the two-stage and three-stage cases.

## Files

- `src/tests/muse-sdk-multistage-live.test.ts`

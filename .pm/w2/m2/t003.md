## Objective

Restore the adapter's truthful-diagnostics contract for failing HTTP MCP endpoints on 1.2.1, or record that the host no longer supplies the signal it depends on.

## Context

- All three `mcp-http-live.test.ts` cases assert the prompt rejects for unauthorized, malformed and unreachable endpoints. On 1.2.1 the prompt resolves `end_turn` instead (line 127).
- The contract was delivered in [w1/m16](../../w1/done/m16/README.md) and documented in `docs/mcp-passthrough.md`; this task restores or amends it on a newer host, and does not redesign it.
- `src/mcp-overlay.ts` and `src/mcp-status.ts` own the private configuration overlay and the last-observed startup failure.
- A silently succeeding prompt after a failed MCP connection is the dangerous direction: the user believes tools were available when they were not. Prefer surfacing over suppressing.

## Steps

1. From t001's evidence, identify any public surface on 1.2.1 that still names the endpoint failure (tool result text, an item, session state, or host stderr already captured by the adapter).
2. If one exists: read it and restore the failing-prompt contract for all three endpoint classes.
3. If none exists: record the host blocker in the milestone README, then decide and implement the honest fallback — at minimum a session-visible warning that the configured MCP server did not connect, so a successful turn is not mistaken for a working tool surface. Update `docs/mcp-passthrough.md` to match.
4. Adjust the three live cases to assert the delivered behavior, keeping them meaningful rather than relaxed to always-pass.

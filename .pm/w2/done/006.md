# 006 — Surface session-state changes the adapter currently folds and ignores

Why: the host publishes approval-mode, model and policy-persistence changes that no adapter code
reads, so a client can be told one thing while the session is doing another.

Phase 2 of the systematic design agreed on 2026-09-13, deferred out of
[m1](m1/README.md). That milestone classified every view event the pinned SDK folds; three
entries in `IGNORED_VIEW_EVENTS` (`src/muse-view-events.ts`) are marked "phase 2" rather than owned
by another milestone:

- `session/approvalModeChanged` — the effective approval mode can change under the session. The
  adapter selects `onRequest` at start and resume and never observes a later change, so an advertised
  mode and the enforced mode can diverge silently.
- `session/modelChanged` — same shape for the model the session is actually using.
- A failed `localPersistent` policy persistence, which the SDK's own fold comments record as dropped
  (their issue #23379): a user picks an allow-always choice, the host fails to persist the rule, and
  nobody is told. The adapter already only offers allow-always when the host lists it, so the gap is
  in reporting the outcome, not in the offer.

Roughly an hour if it stays reporting-only: diff the relevant `fold.sessionState` families on the
existing poll tick and publish changes as negotiated `session_info_update` metadata, the way host
compatibility is published today. It becomes a milestone if acting on a change is in scope — for
example re-synchronizing the advertised ACP mode when the host changes the approval mode, which
touches `src/modes.ts` and `src/config-options.ts` and needs its own real-host evidence.

Do not start this by reopening `IGNORED_VIEW_EVENTS` wholesale: `session/todoListChanged`,
`session/tokenUsage` and `session/contextUsage` belong to [w1/m9](../../w1/evidence/2026-09-14-superseded/m9.md) and
`session/branchChanged` is deliberately unscheduled.

## Triage and outcome (2026-09-14)

Implemented as reporting-only; ACP configuration synchronization remains out of
scope. `session-state-observer.ts` publishes the negotiated `muse/sessionState`
extension from the retained host's existing 100ms timer, including idle changes.
It suppresses unchanged values and waits for a current fold. No policy setter or
new approval choice is introduced.

The initial suggestion of a stdout tap is not available through the pinned
public SDK: `MuseServeChild` exposes exit/stderr/close, not stdout. Using its
internal ownedTransport symbol would violate the board's public-API constraint.
For host-offered localPersistent selections, bounded public `view/page` reads
recover durable policyPersistence facts after the SDK drops them. Choices first
report unverified; only a host report establishes failed or succeeded. Missing
reports remain unverified. This completes reporting without pretending the SDK
can observe facts the host never published. The full tradeoff is recorded by 007.

Coverage includes negotiated versus plain ACP clients, model/mode observation,
idle changes and deduplication, a persistence failure arriving after resolution,
no leaked host failure text, unchanged ACP settings/approval decisions, observer
shutdown, and failed-read fallback. A real-host probe exercises model/mode setters
and public durable page reads. No real policy-write failure is claimed.

Adoption: README, SDK migration contract and Unreleased changelog updated.
Simplification: two state families share one projection/deduplication path and the
existing host timer; persistence reads use observed opaque cursors with no new
notification router, lifecycle owner or raw log parser. The one-second timeout
and unavailable-read latch bound observer traffic without failing a turn.

## Completion evidence

Completed 2026-09-14. `npm run check` and `npm run build` passed;
`npm run test:unit -- --maxWorkers=4` passed 377 tests. Required real-host loopback
suites passed all 29 tests on Muse 1.1.1-R2514.1 and 1.2.1-R2847.1. The final
model probe supplies providerId explicitly, as required by 1.1.1, and passes on
both hosts. The 1.2.1 legacy-reviewer limitation remains an asserted actionable
error, not a successful legacy continuation. Persistence failure coverage uses
the public-wire fixture; real-host coverage proves model/mode events and durable
page reads, not an induced host policy-write failure.

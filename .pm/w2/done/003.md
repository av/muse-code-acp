# 003 — Repeated Allow once confirmations: expected behavior

**Status:** done — closed by triage, not a reproduced approval bug.
**Reported / closed:** 2026-09-13. Closure explicitly approved by the user.

## Report and conclusion

A Bex user reported repeated Allow once / Reject interruptions while asking Muse
to update a dependency and verify it against a small directory. The original
report used adapter 0.4.0; no automatic approval mode had been established as
selected. The original session itself was not replayed.

`Allow once` authorizes the current operation only. In Default / onRequest,
another operation requesting approval is expected. Actual Bex Dev integration
found no lost permission options, extra client-generated approval or failed
decision forwarding. Repeated clicks under this policy are not evidence that an
automatic policy failed. Earlier notes conflated that behavior with the separate
feature request for unattended execution; this conclusion supersedes them.

## Verified evidence

Used native Bex Dev `611f0e3ca5`, local adapter `ed57631`, SDK 0.1.1, isolated
profiles/workspaces and the repository loopback provider with dummy credentials.
No paid model calls were made. Evidence came from ACP frames and actual file
effects; screen capture was unavailable.

| Muse host                                   | Selected mode       | Two-operation task result                                                       |
| ------------------------------------------- | ------------------- | ------------------------------------------------------------------------------- |
| 1.1.1-R2514.1 (supported)                   | Default / onRequest | Each operation required its own AllowOnce; both writes completed after approval |
| 1.2.1-R2847.1 (bounded compatibility probe) | Default / onRequest | Same behavior with latest adapter; prompt completed with end_turn               |

For one prompt containing two shell writes:

1. The first request offered only allow_once and reject_once; neither file existed.
2. Bex returned selected allow_once. The first file contained `debug`; the second
   operation independently requested approval and its file remained absent.
3. After the second AllowOnce, both files contained `debug` and the prompt returned
   end_turn. No allow_always option was offered for Bex to display or discard.

The 1.2.1 probe does not establish general host compatibility. The final two-step
fixtures checked the prompt marker and tool catalog before advancing; an earlier
incomplete fixture attempt is not counted as evidence.

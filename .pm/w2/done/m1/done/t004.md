## Objective

Make host/SDK schema divergence visible to ACP clients and lock the adapter's coverage of SDK view events behind a test that fails when the installed SDK folds a method the adapter has not classified.

## Context

- `src/muse-sdk-host.ts` logs `host.fingerprintWarning` and continues; every run on 1.2.1 prints it. The adapter is verified against `1.1.1-R2514.1` and probed on `1.2.1-R2847.1`, while the Muse launcher auto-updates and removes superseded binaries.
- The SDK folds 21 view events (`node_modules/@muse-code/sdk/dist/src/fold/session-fold.js` `apply` switch) and routes only `turn/*` and `approval/requested` to handlers; the adapter reads `session/goalChanged`, pending counts, items and resolved approvals, and (after t002) pending approvals and user inputs.
- `session_info_update` already carries negotiated `_meta` (`muse/approval`, `muse/activeTurnId`); follow that convention. Do not make a mismatch fatal by default.

## Steps

1. Retain the fingerprint comparison result and host version (from `initializeResult` and the `--version` probe in `src/muse-host.ts`) on the host lease; emit one `session_info_update` per lease with `_meta["muse/hostCompatibility"] = { sdk, pinnedFingerprint, actualFingerprint, matches, hostVersion, verifiedHosts }`. Keep the log line.
2. Add `src/muse-view-events.ts` exporting `HANDLED_VIEW_EVENTS` (method → adapter path that consumes it) and `IGNORED_VIEW_EVENTS` (method → reason and backlog reference such as w1/m9, w1/m14 or "phase 2").
3. Add a test that parses the installed SDK's fold `apply` switch (or its `ViewEvent` union) for method names and asserts the two tables partition that set exactly; a new SDK method must fail the test until classified.
4. Unit-test the metadata emission with the fake host (matching and mismatching fingerprints).

## Acceptance criteria

- [x] After a host lease initializes, clients receive `muse/hostCompatibility` with pinned and actual fingerprints, match state and host version; a mismatch is not fatal.
- [x] Every SDK view-event method is in exactly one table with a reason, and the test fails for an unclassified method.
- [x] `IGNORED_VIEW_EVENTS` entries reference the milestone or phase that owns them.

## Out of scope

- Acting on `session/approvalModeChanged` or `session/modelChanged` (phase 2); a raw stdout notification tap (phase 2); strict-mode refusal of mismatched hosts unless trivially added behind an environment flag.

## Evidence

Delivered: `src/host-compatibility.ts` publishes `_meta["muse/hostCompatibility"]` once per host; `src/muse-view-events.ts` classifies all 22 folded methods and a test fails on an unclassified one. 8 cases in `muse-view-events.test.ts`.

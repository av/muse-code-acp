## Objective

Bound every wait on a pending host request so that a fact the adapter failed to act on becomes a diagnosable turn failure instead of an indefinite hang.

## Context

- The class behind the consumed note w2/004 (README "Issue cause"): the fold holds a pending entity, no handler fires, nothing polls it, and an unattended client waits forever. t002 removes the known instance; this task bounds the unknown ones.
- Observed on 1.2.1: `turn/cancel` while an approval is pending makes the host record `decision_applied abort` and complete the turn, so failing the turn through the existing cancellation path unwinds the host cleanly.
- Anchor points in `src/muse-sdk.ts`: the 25 ms loop, `failTurn`, `interactionsStopped`, `PermissionLifecycle` and `userInputs`.
- Do not fabricate a decision to escape a stall; fail the turn and let the host abort the pending action.

## Steps

1. Track per pending approval and user input: `lastProgressAt` (updated when its fold entry changes identity, for example a new `latestUpdate`, or when the adapter submits a command) and `inFlight` (an ACP request outstanding).
2. In the loop, when an entity is not in flight and `now - lastProgressAt` exceeds the bound (default 10 s; test override via an environment variable documented in t006), call `failTurn` with an error naming the entity id, current requirement (`sourceIndex` of total stages), stage evidence summary and the last folded method for that entity; ensure the existing failure path interrupts the host turn.
3. Reset tracking on turn completion, cancellation and host replacement.
4. Tests with t001 scripts: `decide-then-silence` → the prompt rejects within the bound with the diagnostic message and the fake host receives the turn interruption; `userinput-settle-then-silence` → same for user input; a slow but progressing multi-stage script does not trip the watchdog.

## Acceptance criteria

- [x] A pending approval with no in-flight ACP request and no fold progress for the bound fails the prompt with an error containing the approval id, requirement position and last host event.
- [x] The same bound applies to pending user inputs.
- [x] Progressing approvals, long-running tools and open ACP permission dialogs never trip the watchdog.

## Out of scope

- Adapter-side retries or synthesized decisions; session-state observers (phase 2).

## Objective

Prove on the real Muse host that compound shell commands with multiple unresolved stages complete, and that deny at a later stage executes nothing.

## Context

- `src/tests/muse-sdk-approval-live.test.ts` covers a single-write command only; w2/003 used two separate tool calls. Multi-stage was never exercised live.
- `src/tests/loopback-provider.ts` scripts a `bash` tool call through a fake Meta endpoint with dummy credentials and isolated HOME/XDG; `scriptedToolCallForRequest` can script the compound command once per turn.
- Observed on 1.2.1: the tool runs only after the terminal decision; on abort the tool result is a cancelled approval and no file is written.
- Gate like the existing suite and add the file to the `test:muse-loopback` script so `MUSE_CODE_ACP_REQUIRE_MUSE=1` fails on a missing host rather than skipping.

## Steps

1. Add `src/tests/muse-sdk-multistage-live.test.ts` with an auto-`allow_once` responder that records each request's `museRequirementId` and `muse/approval.stages`.
2. Cases: two-stage (`echo one > a; ls; echo two > b; cat a`) → two requests with `sourceIndex` 0 then 2, both files present, `end_turn`; three-stage → three requests, three files; deny at stage 2 → first request allowed, second denied through the host-offered deny option, no file present, `end_turn`; each case within a bounded timeout so a regression fails instead of hanging.
3. Register the file in `package.json` `test:muse-loopback` and record the host version and results in the milestone's validation evidence.

## Files

## Acceptance criteria

- [x] On the installed supported host, two- and three-stage commands complete with one permission request per unresolved stage and all files written.
- [x] Deny at stage 2 writes nothing and returns `end_turn`.
- [x] The suite is part of `test:muse-loopback` and fails, not skips, without a host when `MUSE_CODE_ACP_REQUIRE_MUSE=1`.

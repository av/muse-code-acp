## Objective

Decide every pending approval requirement from fold state so that multi-stage shell approvals complete on the SDK backend without depending on the SDK router.

## Context

- Today `src/muse-sdk.ts` registers `session.onApproval`, which the SDK only invokes on `approval/requested`; the SDK facade deliberately does not route `approval/updated` (`node_modules/@muse-code/sdk/dist/src/facade/session.js`), and its router discards the decide result, so `terminal` is invisible.
- The fold already stores the refresh: `session.fold.pendingApprovals()[i].latestUpdate` (`ApprovalUpdatedParams` with `currentRequirementId`, `availableChoices`, `subject.stages`). User input is already reconciled by polling in the 25 ms `pumpUserInput` loop; approvals should use the same pattern.
- Proven in triage: submitting `approval/decide` with the `currentRequirementId` from `approval/updated` returns `terminal: true` and the command executes.
- Keep `PermissionLifecycle` stale-guarding (turn and generation), `resolvePermissionChoice` (cancellation maps to a host deny choice, unknown options throw), `fileChanges.beforeApproval` on approved decisions and `publishApprovalResults`.
- Follow `.pm/DO_NOT_DO.md`: only host-offered `choiceId`s, never invent allow-always, no private methods. `approval/decide` is a documented public command.

## Steps

1. Stop registering `session.onApproval` for decisions (retain `onApprovalError` only if it still reports anything useful); add a `reconcileApprovals()` step to the 25 ms loop and run it once before the loop starts so approvals folded before the turn acknowledgement are covered.
2. For each pending approval of the active turn: current requirement and choices come from `latestUpdate` when present, otherwise from `requested`; key decisions by `(approvalId, sourceIndex)`; skip keys already decided or with an ACP request in flight.
3. Build the ACP request through `approvalToPermissionRequest` with the refreshed choices, stages and requirement (extend `MuseApprovalRequest` mapping in `src/muse-permissions.ts` to overlay an update); await `acpClient.requestPermission` racing `interactionsStopped`; map the reply with `resolvePermissionChoice`.
4. Submit `connection.command("approval/decide", { approvalId, choiceId, requirementId: current, sessionId })`. On `MspError` `-32053` mark the key superseded and let the next tick re-read the fold; on `-32052` or other errors fail the turn as today.
5. Tests in `src/tests/permissions.test.ts` using t001 scripts: two-stage → two permission requests with `museRequirementId.sourceIndex` 0 then 2 and two decides echoing those requirements, tool completes, `end_turn`; three-stage → three; deny-at-stage-2 → second request answered with the deny option, approval resolved `abort`, no tool execution, `end_turn`; choices-refresh → options reflect the refreshed choices; a scripted `-32053` → no turn failure and the next requirement is decided; concurrent approvals remain correlated by `approvalId`; cancellation and stale-generation cases from the existing suite still hold.

- [x] `session.onApproval` is no longer the decision path, and no approval is decided twice.

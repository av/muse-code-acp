## Objective

Close only when every failure is fixed or recorded and the definition of done holds.

## Context

- Follow the pm skill `done` procedure: verify acceptance criteria and evidence, archive tasks, then the milestone.
- A recorded host blocker with a reproduction satisfies the definition of done; an unexplained failure does not.

## Steps

1. Verify every task's acceptance criteria and the milestone definition of done against recorded evidence.
2. Use `/pm done` for each remaining task, this one last; move tasks into `done/` and mark table rows.
3. Set milestone `**Status:** done`, move it to `.pm/w2/done/m2/`, check the w2 checkbox and add the Done entry.

## Files

- `.pm/w2/m2/`, `.pm/w2/README.md`

## Acceptance criteria

- [x] All acceptance criteria and the definition of done are satisfied with recorded evidence.
- [x] Task frontmatter, table markers, milestone status, archive paths and the workstream checkbox agree.

## Out of scope

- Publishing a release.

## Completion evidence

Verified all six failures are fixed or recorded with public request/response evidence and a reproducible host limitation, as expressly permitted by the milestone definition. Completed tasks are archived in dependency order, Closeout last; the milestone is moved to w2/done/m2 and its workstream checkbox checked. No npm publication is part of this outcome.

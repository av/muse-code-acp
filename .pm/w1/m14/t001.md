## Objective

Document supported host error kinds, retry events and public credential/account observations; separate credentials configured from authenticated and identity unknown.

## Context

- Why: Error and credential-presence checks obscure recovery choices; this P1 work builds on m9 event reporting.
- Milestone goal: Help clients distinguish waiting, recoverable failures and invalid credentials without guessing from generic errors.
- Reference context: `src/muse-sdk.ts`, `src/auth.ts`, `.tmp/codex-acp/src/CodexEventHandler.ts`, `.tmp/codex-acp/src/AuthStatusMeta.ts`.
- Follow `.pm/DO_NOT_DO.md`. SDK declarations are investigation leads, not proof of real-host support; verify public contracts before advertising capability.

## Steps

1. Probe supported host errors and public auth observations using existing loopback/fake-host harnesses.
2. Record minimum versions, available fields and absent APIs; avoid reading secrets or using a paid model call just to test authentication.

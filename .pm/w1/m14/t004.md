## Objective

Report credential configuration separately from host-observed authentication and optional identity.

## Context

- Why: Error and credential-presence checks obscure recovery choices; this P1 work builds on m9 event reporting.
- Milestone goal: Help clients distinguish waiting, recoverable failures and invalid credentials without guessing from generic errors.
- Reference context: `src/muse-sdk.ts`, `src/auth.ts`, `.tmp/codex-acp/src/CodexEventHandler.ts`, `.tmp/codex-acp/src/AuthStatusMeta.ts`.
- Follow `.pm/DO_NOT_DO.md`. SDK declarations are investigation leads, not proof of real-host support; verify public contracts before advertising capability.

## Steps

1. Replace misleading presence-as-validation claims in authenticate responses and documentation.
2. Publish supported status after initialize/authenticate/logout and verified host changes; preserve environment-key precedence and unknown identity.

## Files

- `src/auth.ts`
- `src/acp-agent.ts`
- `src/tests/auth.test.ts`

## Acceptance criteria

- [ ] Expired stored credentials and invalid keys are not reported as verified merely because they exist.
- [ ] Logout with META_API_KEY still set reports the remaining configured credential correctly; no key or token is emitted.
- [ ] Unavailable public verification yields an explicit unknown/unverified state without claiming logout.

## Out of scope

- Changes to external client UIs, private Muse protocols, fabricated provider state, or unverified control methods.
- Duplicating m8–m13 work, unrelated refactors, paid-provider usage unless independently authorized, and publishing or pushing as part of board maintenance.

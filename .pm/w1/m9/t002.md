## Objective

Provide a /compact command backed by session/compact and observable asynchronous completion.

## Context

- Milestone goal: Let ACP clients observe consumption, context pressure, plans and live progress, and explicitly compact supported sessions.
- Why: The current translator discards richer MSP items and session notifications; expose verified events before introducing more control surfaces.
- Reference context: `src/muse-sdk-events.ts`, `src/muse-sdk.ts`, `.tmp/codex-acp/src/CodexEventHandler.ts`, `.tmp/codex-acp/src/CodexCommands.ts`.
- Follow `.pm/DO_NOT_DO.md`; verify public host behavior before advertising support. Reference schema presence alone is not host acceptance evidence.

## Steps

1. Dispatch the command without submitting it as a model prompt; distinguish admission from completed/noop/failed/cancelled outcomes.
2. Surface automatic and manual compaction items with context information when present; guard busy/close interactions.

## Acceptance criteria

- [ ] Accepted compaction is not reported as complete until a terminal event arrives; noop is handled as success.
- [ ] Failure, cancellation and session close settle pending work and do not launch a duplicate turn.

## Out of scope

## Current blocker (2026-09-12)

Muse 1.1.1-R2514.1 rejects `session/compact` on a durable session after a completed
loopback turn with `-32030 compaction_unavailable`, including with the documented
experimental API opt-in. See the milestone validation evidence and SDK QA D19778.
Accepted/terminal execution proof requires a working supported host; fallback-only
implementation does not satisfy this task.

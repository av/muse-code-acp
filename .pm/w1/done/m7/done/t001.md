## Objective

Make agent disposal terminal for pending load/resume operations as well as active turns, so shutdown cannot be followed by restored adapter state or late session notifications.

## Context

- Read-only review at dfc1d31 found dispose() snapshots current sessions and waits for turnFinished, while load/resume can publish state after asynchronous export or MSP metadata reads.
- This is a code-inspection finding, not a reproduced race; reproduce it before choosing the implementation.

## Steps

1. Add controlled delayed export and MSP metadata-read cases that overlap disposal.
2. Prevent new admission after shutdown starts and ensure pending bindings settle without republishing sessions; track or cancel owned work through public APIs.
3. Cover shutdown during replay, repeated disposal, and existing active-turn cleanup without weakening cancellation behavior.

## Acceptance criteria

- [x] Disposal during delayed load and retained-session resume cannot repopulate sessions after disposal completes.
- [x] Shutdown during history replay emits no new session updates after disposal completes; in-flight operations settle with defined behavior.
- [x] New session/prompt/load/resume admission after disposal is rejected consistently; repeated disposal is safe.
- [x] Tests verify owned host processes and temporary artifacts are cleaned up, using bounded waits rather than arbitrary sleeps.

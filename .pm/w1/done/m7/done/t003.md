## Objective

Carry complete supported resource-link metadata into deterministic prompt context without ambiguous boundaries between fields.

## Context

- formatResourceLink currently drops size and directly interpolates metadata into newline-delimited fields.
- PR #3 proposed escaped structured fields; use its intent while preserving ordered content on both current backends.

## Steps

1. Inspect the pinned ACP ResourceLink schema and define a deterministic escaped encoding for supported metadata.
2. Preserve size, including zero, and distinguish absent values from supplied values where the schema permits.
3. Test Unicode, quotes, newlines and field-looking strings through conversion and both SDK/exec request boundaries; document any encoding change.

## Acceptance criteria

- [x] Supported name, URI, size, title, description and MIME metadata survive encoding without silently dropping supplied values.
- [x] Quotes, newlines and field-looking values cannot be confused with additional metadata fields; tests check recoverable values rather than a whole-output snapshot.
- [x] Text/resource/image ordering remains intact on the SDK path and resource-link-only prompts work on both backends.
- [x] Resource URIs are never fetched by conversion; audio and embedded-resource capability claims remain unchanged.

## Out of scope

- Fetching resources, supporting audio/embedded resources, or treating prompt formatting as a security boundary.

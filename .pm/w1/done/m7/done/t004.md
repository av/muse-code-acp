## Objective

Extend the PRs' execution-proof approach to combinations of session lifecycle, permissions, elicitation and images that existing isolated tests do not fully cover.

## Context

- SDK close is tested with a blocked text turn; cancellation and stale elicitation replies have separate coverage.
- The real-host image test covers text plus PNG bytes; image-only SDK behavior needs explicit evidence.

## Steps

1. Add close while permission and elicitation replies remain unanswered, followed by late replies after close and after retained-session resume.
2. Assert that stale decisions do not answer a new request, authorize a tool, or affect another session; prove the resumed session can complete a new turn.
3. Probe image-only SDK input against the pinned real host and encode the supported outcome in tests and documentation; if unsupported, reject it clearly before turn execution.
4. Keep fake-MSP/wire tests deterministic and use the existing loopback provider for real execution evidence.

## Acceptance criteria

- [x] Close settles without requiring an unanswered permission or elicitation dialog to return, and the cancelled prompt settles.
- [x] Late replies after close/resume cannot grant permission, submit stale input, or mutate a replacement turn; a new turn still succeeds.
- [x] A real-host approval test proves a tool awaiting permission does not execute because of a stale allow reply.
- [x] Image-only SDK behavior is verified against the supported host and is consistent with advertised/documented behavior; existing text-plus-image and exec restrictions remain covered.

## Out of scope

- Paid-provider calls as a mandatory CI dependency, fabricated permissions, or enabling unsupported content capabilities.

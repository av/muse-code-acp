## Objective

Apply the existing resume directory and canonical-path guarantees consistently to session creation and history loading.

## Context

- resume validates a real directory and stores its canonical path; new only checks for an absolute path, and load retains params.cwd.
- Preserve retained-session workspace ownership and the explicit single-workspace contract.

## Steps

1. Identify a shared validation seam for new/load/resume, keeping errors actionable and consistent.
2. Validate an existing directory and retain its canonical target before asynchronous work or session-state publication.
3. Add tests for missing paths, files, equivalent symlinks, changed roots, and symlink retargeting after admission.

## Acceptance criteria

- [x] New/load/resume reject missing directories, regular files, and relative paths before publishing session state.
- [x] Equivalent symlinks are accepted and canonical directories are stored for all three operations.
- [x] Retargeting the originally supplied symlink does not redirect subsequent work to another workspace.
- [x] Load/resume still reject a different retained-session workspace; rejected requests leave prior state and MCP settings unchanged.

## Out of scope

- Additional workspace support, changing stored Muse history, or replacing the official SDK.
